# Iris/Sodium Render Target Integration Design

## Goal

Replace the prototype's vanilla framebuffer ownership assumption with a version-locked Iris 1.8.14 beta.1 / Sodium 0.8.12 beta.2 integration for Minecraft 1.21.1, while retaining the proven OpenGL-D3D12 DLSS transport.

## Development Matrix

- Fabric: Iris `1.8.14-beta.1+1.21.1-fabric`, Sodium `mc1.21.1-0.8.12-beta.2-fabric`.
- NeoForge target: the user's existing `iris-neoforge-1.8.14-beta.1+mc1.21.1` and `sodium-neoforge-0.8.12-beta.2+mc1.21.1`.
- Start with Fabric because the live controller already exists there; keep Iris-facing contracts loader-neutral and port the final hook to NeoForge afterward.

## Resource Source

When Iris is active, obtain the current `WorldRenderingPipeline` from `Iris.getPipelineManager()`. For `IrisRenderingPipeline`, a version-locked mixin accessor exposes its `RenderTargets` instance.

The adapter reports:

- active pipeline type and shaderpack state;
- render target width/height;
- current `colortex0` main/alternate texture selection;
- current depth texture;
- pre-translucent and pre-hand depth texture availability;
- finalization phase and pipeline generation.

No Java reflection is used for private targets. If the accessor cannot apply to the locked Iris version, the integration disables itself with a version-contract error.

## Frame Flow

With Iris/Sodium present but no shaderpack, keep the existing low-resolution world redirection only as a compatibility baseline while sourcing color/depth identity from Iris diagnostics.

With a shaderpack active:

1. Iris owns gbuffer and composite targets.
2. The DLSS hook executes after Iris has finalized the world scene but before hand/HUD composition.
3. The adapter chooses the actually readable final scene color target based on Iris flip state.
4. Depth comes from Iris's current main depth target; pre-hand depth is preferred when hand exclusion is needed.
5. Camera motion remains generated by the proven shader initially; shaderpack/object motion is reported unsupported until a separate contract is implemented.
6. DLSS output is composited before native-resolution hand/HUD rendering.

The prototype must not claim shaderpack compatibility until target selection and visual output are verified with an active pack.

## Safety And Fallback

Iris absent: retain the verified vanilla prototype only under an explicit development property.

Iris present but incompatible version/pipeline/target: do not install the Live DLSS redirector; show `IRIS_CONTRACT_UNAVAILABLE` and leave Iris/Sodium rendering untouched.

Shader reload, dimension change, pipeline generation change, or target resize closes the current DLSS session and resets temporal history before reopening.

## Acceptance

1. Fabric client log proves exact Iris and Sodium versions loaded.
2. Overlay reports Iris pipeline, target dimensions, color texture, depth texture, shaderpack state, and pipeline generation.
3. No-shaderpack Iris/Sodium reaches a world without viewport or outline regressions.
4. Active shaderpack run captures stable Iris color/depth targets and either reaches DLSS output or records the exact remaining incompatibility without falling back to pretending vanilla resources are Iris resources.
5. NeoForge adapter is only started after the Fabric Iris contract is green.

## Deferred

Entity-local motion, shaderpack-provided motion vectors, reactive masks, multi-target HDR/exposure mapping, NeoForge packaging, and the single-JAR native distribution are deferred until Iris resource ownership is proven.
